# Remarker 第二版需求（PRD）

> 基于 v0.1.0 代码库的功能分析，从功能角度梳理可改进和升级的点。

---

## 一、词汇学习闭环（优先级最高）

### 1.1 现状

查词后自动保存到词汇表，但词汇表只做被动存储，没有复习/消化环节。README roadmap 已提到遗忘曲线复习，但尚未实现。

### 1.2 改进点

| 编号 | 功能             | 说明                                                                                                                                                                                                                   |
| ---- | ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| V-01 | 间隔重复复习系统 | 基于 SM-2 或 FSRS 算法，为每条词汇计算下次复习时间，提供"今日待复习"卡片界面                                                                                                                                           |
| V-02 | 复习界面         | 在 options 的生词本页面新增 tabs 放在标题栏的最右侧，包含 阅读视图 和 复习视图 两个标签，其中 阅读视图 展示目前的内容，复习视图 展示待复习的内容。展示单词 → 点击翻转查看释义 → 自评熟悉度（生疏/犹豫/熟练）→ 自动排期 |
| V-03 | 复习提醒         | 通过 `chrome.alarms` 定时触发复习提醒 badge，在扩展图标上显示待复习量，在扩展图标的 popup 中展示 "进入复习界面" 按钮，点击后跳转到复习界面                                                                             |
| V-04 | 词汇掌握度       | `VocabularyRecord` 增加 `reviewCount`、`easinessFactor`、`nextReviewAt`、`lastReviewAt` 字段，跟踪学习度                                                                                                               |

---

## 二、LLM 交互体验

### 2.1 现状

LLM 调用是完整返回后再渲染，用户等待时间长（尤其是翻译长文本）。prompt template 是全局唯一的，不能按任务类型细化。

### 2.2 改进点

| 编号 | 功能                  | 说明                                                                                                                                                    |
| ---- | --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| L-01 | 流式响应（Streaming） | 使用 `fetch` + `ReadableStream` 实现 SSE 解析，内容逐字/逐句渲染到 panel，大幅改善体感速度。`callOpenAiCompatibleApi` 改为 `async function*` 或回调模式 |

---

## 三、阅读交互增强

### 3.1 现状

工具栏只提供基础操作（复制/搜索/发音/解释/翻译/划线），划线后点击已有划线可改色/删除。

### 3.2 改进点

| 编号 | 功能                      | 说明                                                                                                                                                                                                                                     |
| ---- | ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R-01 | 划线添加笔记              | 划线后可附加文字笔记，在管理页面和高亮 hover 时展示。`HighlightRecord` 增加 `note?: string` 字段，在二次点击高亮区域弹出的编辑工具条中展示笔记按钮，点击后弹出一个弹窗然用户输入笔记，可以保存或取消，hover 时展示笔记最多展示 56 个字符 |
| R-02 | 修正 content 浮层滚动问题 | 现在在渲染查词或翻译的内容后，如果在浮层内部需要滚动，但滚动到了顶部或底部继续滚动，就会开始滚动页面，希望当鼠标在浮层区域时禁止滚动页面                                                                                                 |
| R-03 | 选中文字后工具栏能否兼容  | 当我在已经划线的一段文字中，再次选中一个单词，现在单词的工具栏是无法弹出的（因为会弹出修改划线的工具栏），能不能有一个方案实现兼容（把查词/翻译的按钮融入到划线修改工具栏中也可以）                                                      |
| R-04 | 划线导出格式增强          | 导出为 Markdown 时带 Obsidian frontmatter、增加 Notion 格式选项                                                                                                                                                                          |
| R-05 | 暗色模式                  | 工具栏/面板 Shadow DOM 的样式支持 `prefers-color-scheme: dark`，在暗色网页上不会刺眼                                                                                                                                                     |

## 四、词汇/翻译管理增强

### 4.1 现状

词汇和翻译分两个 tab 展示，每条记录可展开查看详情。筛选维度有限（词/上下文/来源）。

### 4.2 改进点

| 编号 | 功能     | 说明                                                                              |
| ---- | -------- | --------------------------------------------------------------------------------- |
| M-01 | 发音缓存 | 获取过的发音音频缓存到 IndexedDB，避免重复请求（尤其 Merriam-Webster 有频率限制） |

---

## 五、数据同步与备份

### 5.1 现状

数据完全本地，手动 JSON 导入导出。Roadmap 提到跨设备同步。

### 5.2 改进点

| 编号 | 功能       | 说明                                                                                                                       |
| ---- | ---------- | -------------------------------------------------------------------------------------------------------------------------- |
| S-01 | 自动备份   | 定期（如每天）自动导出 JSON 到用户指定目录，通过 Chrome downloads API + 用户配合                                           |
| S-02 | 跨设备同步 | 利用 `chrome.storage.sync`（有 100KB 限制）存储轻量配置和站点设置；对于大数据，可支持 WebDAV、GitHub Gist 或自建服务端同步 |
| S-03 | 增量导出   | 支持"仅导出上次导出后的新增/变更记录"，避免每次都导出全量                                                                  |

## 六、非拉丁语言支持

### 6.1 现状

`WORD_PATTERN = /^[A-Za-z]+(?:[-'][A-Za-z]+)*$/` 只匹配拉丁字母单词。对中文、日文、韩文等 CJK 文本无法触发"解释单词"模式。

### 6.2 改进点

| 编号 | 功能         | 说明                                                                                                   |
| ---- | ------------ | ------------------------------------------------------------------------------------------------------ |
| C-01 | CJK 选词识别 | 增加 CJK 字符匹配：单个/多个汉字、日语假名、韩文。选中单个汉字时按"查词"处理，选中多个汉字时按场景判断 |
| C-02 | 分词优化     | 对中文选中内容，可基于简单的分词规则（或调用轻量词典）判断选中内容是否为"词"级别                       |

---

## 七、Pronunciation 发音增强

### 7.1 现状

仅对拉丁单词提供发音，使用 Merriam-Webster → Free Dictionary → SpeechSynthesis 降级链。CJK 词汇不触发发音。

### 7.2 改进点

| 编号 | 功能       | 说明                                                                                      |
| ---- | ---------- | ----------------------------------------------------------------------------------------- |
| P-01 | 多语言发音 | 中文使用 SpeechSynthesis 时指定 `zh-CN`/`zh-TW` voice；日语指定 `ja-JP`；韩语指定 `ko-KR` |
| P-02 | 音标展示   | 在查词结果/MD 内容中保留音标信息（Merriam-Webster API 返回中包含）                        |

## 八、架构与性能

### 8.1 现状

整体架构清晰，但存在一些可优化的点。

### 8.2 改进点

| 编号 | 功能                    | 说明                                                                                                                                      |
| ---- | ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| A-01 | 批量恢复优化            | `restoreHighlights` 和 `restoreVocabularyMarkers` 对每条记录独立创建 Range + surroundContents，当记录量大时可能卡顿。可批量测量、批量插入 |
| A-02 | IndexedDB 查询优化      | `getAllFromStore` 获取全量后在内存中 filter，当数据量大时应使用 index 游标分页查询                                                        |
| A-03 | Content Script 启动延迟 | 当前 content script 在页面加载后立即执行 restore，可能影响页面性能。可考虑 `requestIdleCallback` 延迟非关键恢复                           |

---

## 九、用户引导与体验

### 9.1 现状

安装后无引导，用户需要自行探索。

### 9.2 改进点

| 编号 | 功能         | 说明                                                                                                       |
| ---- | ------------ | ---------------------------------------------------------------------------------------------------------- |
| U-01 | 首次使用引导 | 安装后引导用户进入设置，配置 LLM （告诉用户配置了 LLM 才能使用划线查词和翻译功能）                         |
| U-02 | 空状态优化   | Footprints/Highlights/Vocabulary 的空状态已有提示文字，可增加操作引导（如"去浏览一篇文章试试"的 CTA 按钮） |
| U-03 | 错误诊断增强 | 当 LLM 配置不完整时，报错信息可以更具体地指出缺少 baseUrl / apiKey / model 中的哪一项                      |
