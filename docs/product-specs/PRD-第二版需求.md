# Remarker 第二版需求（PRD）

> 基于 v0.1.0 代码库的功能分析，从功能角度梳理可改进和升级的点。

---

## 一、词汇学习闭环（优先级最高）

### 1.1 现状

查词后自动保存到词汇表，但词汇表只做被动存储，没有复习/消化环节。README roadmap 已提到遗忘曲线复习，但尚未实现。

### 1.2 改进点

| 编号 | 功能 | 说明 |
|------|------|------|
| V-01 | 间隔重复复习系统 | 基于 SM-2 或 FSRS 算法，为每条词汇计算下次复习时间，提供"今日待复习"卡片界面 |
| V-02 | 复习界面 | 在 options 页面新增 Review 标签，展示单词 → 点击翻转查看释义 → 自评熟悉度（生疏/犹豫/熟练）→ 自动排期 |
| V-03 | 复习提醒 | 通过 `chrome.alarms` 定时触发复习提醒 badge，在扩展图标上显示待复习数量 |
| V-04 | 词汇掌握度 | `VocabularyRecord` 增加 `reviewCount`、`easinessFactor`、`nextReviewAt`、`lastReviewAt` 字段，跟踪学习进度 |

---

## 二、LLM 交互体验

### 2.1 现状

LLM 调用是完整返回后再渲染，用户等待时间长（尤其是翻译长文本）。prompt template 是全局唯一的，不能按任务类型细化。

### 2.2 改进点

| 编号 | 功能 | 说明 |
|------|------|------|
| L-01 | 流式响应（Streaming） | 使用 `fetch` + `ReadableStream` 实现 SSE 解析，内容逐字/逐句渲染到 panel，大幅改善体感速度。`callOpenAiCompatibleApi` 改为 `async function*` 或回调模式 |
| L-02 | 分任务 Prompt 模板 | 允许用户分别配置"查词"和"翻译"两套 prompt，不再共用一个模板。settings 中 `promptTemplate` 拆分为 `explainPromptTemplate` 和 `translatePromptTemplate` |
| L-03 | 追问/对话 | 查词/翻译结果面板增加追问输入框，允许在上下文中继续提问，实现多轮对话 |
| L-04 | 一键页面摘要 | 对当前页面选中区域或全文，调用 LLM 生成摘要/要点，适合长文阅读场景 |

---

## 三、阅读交互增强

### 3.1 现状

工具栏只提供基础操作（复制/搜索/发音/解释/翻译/划线），划线后点击已有划线可改色/删除。

### 3.2 改进点

| 编号 | 功能 | 说明 |
|------|------|------|
| R-01 | 划线添加笔记 | 划线后可附加文字笔记，在管理页面和高亮 hover 时展示。`HighlightRecord` 增加 `note?: string` 字段 |
| R-02 | 右键菜单集成 | 添加 Chrome `contextMenus`：选中文本后右键 → "解释"/"翻译"/"划线"/"发音"，无需先点工具栏 |
| R-03 | 键盘快捷键 | 选中文本后快捷键触发解释（如 `Ctrl+Shift+E`）、翻译（`Ctrl+Shift+T`）、划线（`Ctrl+Shift+H`） |
| R-04 | 划线导出格式增强 | 增加导出为 Anki CSV/APKG、Obsidian Markdown（带 frontmatter）、Notion 格式等选项 |
| R-05 | 暗色模式 | 工具栏/面板 Shadow DOM 的样式支持 `prefers-color-scheme: dark`，在暗色网页上不会刺眼 |

---

## 四、词汇/翻译管理增强

### 4.1 现状

词汇和翻译分两个 tab 展示，每条记录可展开查看详情。筛选维度有限（词/上下文/来源）。

### 4.2 改进点

| 编号 | 功能 | 说明 |
|------|------|------|
| M-01 | 标签/分类 | 词汇和翻译支持用户自定义标签（如"技术"、"文学"、"日常"），按标签筛选和分组导出 |
| M-02 | 批量操作 | 支持多选后批量删除、批量导出、批量添加标签 |
| M-03 | 词汇搜索增强 | 增加按 model 筛选（来自不同 LLM 的结果可能有差异）、按日期范围筛选 |
| M-04 | 词汇统计仪表盘 | 新增简单的统计视图：总词汇量、本周新增、复习进度、高频来源站点排名 |
| M-05 | 发音缓存 | 获取过的发音音频缓存到 IndexedDB，避免重复请求（尤其 Merriam-Webster 有频率限制） |

---

## 五、数据同步与备份

### 5.1 现状

数据完全本地，手动 JSON 导入导出。Roadmap 提到跨设备同步。

### 5.2 改进点

| 编号 | 功能 | 说明 |
|------|------|------|
| S-01 | 自动备份 | 定期（如每天）自动导出 JSON 到用户指定目录，通过 Chrome downloads API + 用户配合 |
| S-02 | 跨设备同步 | 利用 `chrome.storage.sync`（有 100KB 限制）存储轻量配置和站点设置；对于大数据，可支持 WebDAV、GitHub Gist 或自建服务端同步 |
| S-03 | 增量导出 | 支持"仅导出上次导出后的新增/变更记录"，避免每次都导出全量 |

## 六、非拉丁语言支持

### 6.1 现状

`WORD_PATTERN = /^[A-Za-z]+(?:[-'][A-Za-z]+)*$/` 只匹配拉丁字母单词。对中文、日文、韩文等 CJK 文本无法触发"解释单词"模式。

### 6.2 改进点

| 编号 | 功能 | 说明 |
|------|------|------|
| C-01 | CJK 选词识别 | 增加 CJK 字符匹配：单个/多个汉字、日语假名、韩文。选中单个汉字时按"查词"处理，选中多个汉字时按场景判断 |
| C-02 | 分词优化 | 对中文选中内容，可基于简单的分词规则（或调用轻量词典）判断选中内容是否为"词"级别 |

---

## 七、Pronunciation 发音增强

### 7.1 现状

仅对拉丁单词提供发音，使用 Merriam-Webster → Free Dictionary → SpeechSynthesis 降级链。CJK 词汇不触发发音。

### 7.2 改进点

| 编号 | 功能 | 说明 |
|------|------|------|
| P-01 | 多语言发音 | 中文使用 SpeechSynthesis 时指定 `zh-CN`/`zh-TW` voice；日语指定 `ja-JP`；韩语指定 `ko-KR` |
| P-02 | 发音按钮自动播放 | Vocabulary tab 的发音按钮已存在，增加"自动播放"开关 |
| P-03 | 音标展示 | 在查词结果/MD 内容中保留音标信息（Merriam-Webster API 返回中包含） |

---

## 八、Footprint 功能扩展

### 8.1 现状

Footprint 记录浏览过的页面，支持 star 和 archive，展示划线数和词汇数。

### 8.2 改进点

| 编号 | 功能 | 说明 |
|------|------|------|
| F-01 | 阅读进度追踪 | Footprint 增加"阅读进度百分比"或"最后滚动位置"，帮助用户恢复阅读上下文 |
| F-02 | 站点聚合视图 | 按站点/域名聚合，展示"该站点共阅读 N 篇文章，M 条划线，K 个词汇" |
| F-03 | 阅读时长统计 | 粗略估计在页面的停留时间（通过 content script 定时心跳上报） |

## 九、架构与性能

### 9.1 现状

整体架构清晰，但存在一些可优化的点。

### 9.2 改进点

| 编号 | 功能 | 说明 |
|------|------|------|
| A-01 | LLM 调用缓存粒度 | 当前缓存 key 包含完整 context hash，导致同一词汇在稍有不同的上下文中会重复请求。可考虑"相似上下文"去重 |
| A-02 | 批量恢复优化 | `restoreHighlights` 和 `restoreVocabularyMarkers` 对每条记录独立创建 Range + surroundContents，当记录量大时可能卡顿。可批量测量、批量插入 |
| A-03 | IndexedDB 查询优化 | `getAllFromStore` 获取全量后在内存中 filter，当数据量大时应使用 index 游标分页查询 |
| A-04 | Content Script 启动延迟 | 当前 content script 在页面加载后立即执行 restore，可能影响页面性能。可考虑 `requestIdleCallback` 延迟非关键恢复 |

## 十、用户引导与体验

### 10.1 现状

安装后无引导，用户需要自行探索。

### 10.2 改进点

| 编号 | 功能 | 说明 |
|------|------|------|
| U-01 | 首次使用引导 | 安装后打开一个简单的 onboarding 页面或 step-by-step 引导，教用户配置 LLM、做第一次划线/查词 |
| U-02 | 空状态优化 | Footprints/Highlights/Vocabulary 的空状态已有提示文字，可增加操作引导（如"去浏览一篇文章试试"的 CTA 按钮） |
| U-03 | 错误诊断增强 | 当 LLM 配置不完整时，报错信息可以更具体地指出缺少 baseUrl / apiKey / model 中的哪一项 |
